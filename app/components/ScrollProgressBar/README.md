# ScrollProgressBar

Декоративный индикатор прокрутки документа без клиентского JavaScript.

```tsx
import { ScrollProgressBar } from "@/app/components/ScrollProgressBar";

<div>
  <header>{/* Обычная прокручиваемая шапка */}</header>
  <ScrollProgressBar color="#f3b941" height={3} className="sticky top-0 z-30" />
  <main>{/* Содержимое страницы */}</main>
</div>
```

Props: `color` — CSS-цвет (по умолчанию `#2563eb`), `height` — толщина в px
(по умолчанию 3), `className` — необязательный дополнительный класс.

Позиционированием внешнего контейнера управляет `className`; CSS компонента
не задаёт ему `position`, `top` или `bottom`. Анимируется только внутреннее заполнение.
Фон дорожки также можно задать классом, например `bg-[#10211d]`.

Если должна закрепляться только полоса, размещайте её **рядом с header, а не внутри**:
sticky не может выйти за нижнюю границу своего родителя. Общий контейнер должен
охватывать всю страницу. У него не должно быть `overflow: hidden/auto` без собственной
прокрутки; для горизонтального обрезания подходит `overflow-x: clip`.
На `/donetsk` шапка уходит вверх, а полоса закрепляется, достигнув верхнего края окна.

CSS `scroll(root block)` связывает заполнение с прокруткой всей страницы:
начало — 0%, конец — 100%, без плавного запаздывания. При раскрытии FAQ или
изменении размера окна браузер пересчитывает диапазон сам. На непрокручиваемой
странице timeline неактивен и заполнение остаётся нулевым.

Без поддержки scroll timeline индикатор скрыт. Также скрыт при
`prefers-reduced-motion: reduce` и печати. JS-polyfill намеренно не добавлен.
`aria-hidden` исключает декоративную полоску из accessibility tree;
она не перехватывает клики и не получает клавиатурный фокус.

Компонент не требует JS; это не отменяет возможные ограничения SSR/streaming
самой страницы. Известное ограничение `/donetsk` описано в `docs/donetsk-performance.md`.

Справка: [CSS scroll progress](https://developer.mozilla.org/en-US/blog/scroll-progress-animations-in-css/).
