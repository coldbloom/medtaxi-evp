# Статический экспорт и загрузка на VPS

`yarn build` создаёт каталог `out/` с HTML, JavaScript, CSS, изображениями,
`robots.txt`, `sitemap.xml` и `services-feed.xml`. Серверные компоненты выполняются
при сборке; страницы, canonical, метаданные и JSON-LD сохраняются в HTML.
Слайдеры, меню, FAQ и формы продолжают работать в браузере.

Настройка соответствует [статическому экспорту Next.js](https://nextjs.org/docs/app/guides/static-exports):
`output: "export"`, URL без завершающего слеша, статические GET-обработчики и заранее
перечисленные страницы услуг. `next export` и `next start` для публикации не нужны.

## API перед сборкой

Обратный звонок отправляет POST в `${NEXT_PUBLIC_API_URL}/feedback`, а аналитика
телефонных ссылок — в `${NEXT_PUBLIC_API_URL}/call-clicks`. Этот backend работает
отдельно; загрузка `out/` не устанавливает и не перезапускает его.

В корне проекта создайте или обновите `.env.production.local`, указав **реальный
рабочий адрес API**. Пример формата, не адрес для публикации:

```dotenv
NEXT_PUBLIC_API_URL=https://api.example.com/api
```

Шаблон находится в `.env.example`; файлы `.env*.local` исключены из Git.
При `next build` адрес проверяется: пустое значение, HTTP, localhost/loopback,
логин/пароль в URL, параметры запроса или фрагмент останавливают сборку.
Это проверка конфигурации, а не доступности backend или его CORS.

Если API доступен на том же домене через существующий Nginx proxy, допустим базовый
путь `/api`. Сохраните соответствующий `location /api/` на VPS. Для API на другом
домене backend должен разрешать origin `https://medtaxi-evp.ru` для формы и трекинга.
На HTTPS-сайте используйте HTTPS API. Не оставляйте localhost в production-сборке.

`NEXT_PUBLIC_API_URL` встраивается в JavaScript во время сборки на Mac. Изменение
переменной только на VPS не обновит загруженный сайт. Переменная из shell имеет
приоритет над `.env.production.local`; не оставляйте в ней адрес локального API.
Не помещайте пароли и токены в `NEXT_PUBLIC_*` или в `public/`.
Подробнее: [переменные окружения Next.js](https://nextjs.org/docs/app/guides/environment-variables).

## Сборка на Mac

```bash
cd /Users/konstantin.kolesnik/Documents/code/perevozki/medtaxi-evp
git pull --ff-only
yarn install --immutable
yarn build:export
```

Команда запускает ESLint, все тесты, `next build` (включая TypeScript) и
`check:export`. Обычная последовательность `yarn build && yarn check:export`
также поддерживается. Для отдельной проверки типов используйте `yarn typecheck`.
Версии Next.js и eslint-config-next зафиксированы на 16.4.2; устанавливайте
зависимости по обновлённому `yarn.lock`.

`git pull` нужен при получении уже опубликованных в Git изменений; локальные
незакоммиченные изменения сначала сохраните. Если сборка или проверка завершились
ошибкой, не загружайте оставшийся `out/` на сервер.

Посмотреть результат именно статической сборки:

```bash
yarn start --port 3081
```

Откройте `/`, `/donetsk`, `/donetsk/moskva`, страницу услуги, `/robots.txt` и
`/sitemap.xml` на `http://localhost:3081`. Несуществующий URL должен возвращать 404.
Локальная проверка артефактов не подтверждает доступность production backend.
При тестировании отправки формы обращение действительно попадёт в настроенный API.

## Nginx на VPS

Адаптируйте [пример](../deploy/nginx-static.conf.example) внутри существующего
`server {}` для `medtaxi-evp.ru`. Укажите фактический `root` каталога со статикой.
Сохраните HTTPS, сертификаты, перенаправление HTTP → HTTPS и существующие proxy
маршруты backend. Пример не является заменой полного конфига домена.
Если защитные заголовки заданы через `add_header` на уровне `server`, включите их
также в новые `location`: локальный `add_header Cache-Control` меняет наследование.

Правило `try_files` проверяет `.html` **до каталога**: `/donetsk.html` должен
отдаваться по адресу `/donetsk`, даже когда рядом есть папка `/donetsk/` с фотографиями
и страницей Москвы. Нельзя подменять отсутствующие страницы `/index.html`: это
превратит реальные 404 в ответы 200. В примере также сохраняются URL без завершающего
слеша, а HTML и данные навигации требуют перепроверки кеша.

Годовой immutable-кеш разрешён для сборочных файлов `/_next/static/` и изображений
с хешем в `/donetsk/images/`. Остальные файлы не получают такое правило. Для
изображений Донецка и Mercedes уже подготовлены AVIF/WebP разных размеров.
Остальные `next/image` используют исходные файлы (`unoptimized: true`), поскольку
серверный обработчик `/_next/image` в экспорте отсутствует.

Копируйте весь `out/`, включая файлы `.txt` с данными навигации App Router.
Проверка экспорта отклоняет сборку, если такой файл отсутствует у страницы sitemap.

После изменения конфигурации на VPS:

```bash
nginx -t && systemctl reload nginx
```

## Загрузка через rsync

Каталог назначения должен содержать только опубликованный фронтенд: `--delete`
удалит файлы, которых нет в `out/`. Backend, загруженные пользователями файлы и
другие сайты должны находиться отдельно. `/var/www/oknoshield/` из инструкции другого
проекта не является подтверждённым каталогом Медтакси.

На Mac замените `VPS_HOST` и путь на фактические значения из конфигурации домена:

```bash
MEDTAXI_DEPLOY_TARGET='root@VPS_HOST:/ABSOLUTE/PATH/TO/MEDTAXI_STATIC/'
chmod -R a+rX out
rsync -avzn --delete out/ "$MEDTAXI_DEPLOY_TARGET"
```

Проверьте каталог и список изменений dry run. Затем загрузите ту же сборку:

```bash
rsync -avz --delete out/ "$MEDTAXI_DEPLOY_TARGET"
```

Завершающий слеш в `out/` означает копирование его содержимого. Не загружайте
`node_modules`, `.next`, `.env*` или исходный код. При обычном обновлении файлов
перезапуск Nginx не требуется. Синхронизация в действующий каталог не атомарна:
во время загрузки возможна смесь файлов двух сборок. Для публикации без этого окна
используйте отдельный каталог релиза с переключением `root`/символической ссылки.
Даже при переключении релизов уже открытые вкладки могут запросить JS предыдущей
сборки: при необходимости сохраняйте её хешированные `/_next/static/` ресурсы
на время перехода. Не применяйте `--delete` к общему архиву таких ресурсов.

После публикации проверьте загрузку `/donetsk` и `/donetsk/moskva` напрямую,
переходы между страницами, фотографии, FAQ, телефонные ссылки, обратный звонок и
наличие нового адреса в sitemap. В Network проверьте отправку на нужный API без
ошибок CORS. Повторно обойти новую страницу можно через Яндекс Вебмастер.

## Ограничения для следующих изменений

Новые страницы из динамических маршрутов должны попадать в `generateStaticParams`.
Для этих заранее собранных страниц удалены маршрутные `loading.tsx`:
[документация loading.js](https://nextjs.org/docs/app/api-reference/file-conventions/loading#platform-support)
не заявляет поддержку статического экспорта. После обновления Next.js проверяйте,
что границы Suspense не оставляют основной текст
в скрытом контейнере, который требует JavaScript. `check:export` проверяет наличие
H1 каждой страницы sitemap в видимом содержимом `main`; CSS и поведение без
JavaScript дополнительно проверяются в браузере.
Изменение контента, sitemap или XML-фида требует пересборки. Обработчики POST,
Server Actions, cookies/headers запроса и ISR требуют отдельного сервера и не
добавляются в этот статический фронтенд. Серверные redirects, rewrites и HTTP-заголовки
настраиваются в Nginx, а не в `next.config.ts`.
