# Производительность /donetsk

Страница предварительно генерируется Next.js и отдаётся через `next start`.
Тексты, SEO-разметка, видео, фотографии,
ссылки и кнопки рендерятся на сервере. Один `DonetskInteractions` обрабатывает
цели Метрики и открытие формы. Код формы подгружается при первом открытии.
Секции страницы и данные находятся в `src/features/donetsk/`; декомпозиция
не переносит основной контент в клиентский JavaScript.

## Видео в Hero

`DonetskHeroVideo` выводит нативный `<video>` без отдельной JS-библиотеки плеера.
Исходный `public/donetsk/video/stretcher-on-lift.mp4` сохранён без изменений.
Страница использует сжатые копии из `public/donetsk/video/generated/`;
их пути и размеры находятся в `app/donetsk/video.generated.ts`.
Это вертикальный ролик длительностью 7,5 секунды, 30 кадров в секунду.
`autoPlay`, `muted`, `loop`, `playsInline`
включают повторение без звука; нативные `controls` позволяют остановить ролик
и запустить его вручную, если браузер заблокировал автозапуск.

| Ширина экрана | Размер видео | WebM (VP9) | MP4 (H.264) |
| --- | --- | ---: | ---: |
| До 767 px | 540×960 | 845 КБ | 762 КБ |
| От 768 px | 720×1280 | 1 205 КБ | 1 194 КБ |

КБ = 1000 байт. Для сравнения: исходные WebM и MP4 весят 2,07 и 2,53 МБ.
Браузер выбирает подходящий `<source>` по `media` и поддержке формата;
оба формата скачивать не требуется. У производных файлов удалена аудиодорожка,
MP4 подготовлены с `faststart`: метаданные находятся до видеоданных.

Пропорции 9:16 и размеры зарезервированы до загрузки. Видео показывается целиком,
без обрезки. WebP-постер первого кадра весит 54 КБ. Его предзагрузка с высоким
приоритетом включена только от 1024 px, где плеер находится рядом с текстом Hero.
На телефоне постер загружается обычным способом через атрибут `poster`.
`preload="metadata"` является подсказкой браузеру; автозапуск требует загрузки
выбранного видео и имеет приоритет над ней. Это не отложенная загрузка видео.
Подпись сообщает, что ролик без звука; отдельная ссылка позволяет открыть MP4.

Имена производных содержат SHA-256-хеш. `next.config.ts` задаёт
`Cache-Control: public, max-age=31536000, immutable` только пяти точным адресам
из manifest. Nginx передаёт этот заголовок от Next.js; дополнительных правил
для видео не требуется. Исходные файлы не получают бессрочный кеш.

Для обновления после замены исходного MP4 установите FFmpeg с кодеками
`libvpx-vp9` и `libx264`, затем выполните:

```sh
yarn optimize:donetsk-video
# Если FFmpeg не в PATH:
FFMPEG_PATH=/absolute/path/to/ffmpeg yarn optimize:donetsk-video
```

Команда создаёт четыре видео и постер, обновляет manifest. Эти файлы нужно
включить в коммит. FFmpeg не нужен для `yarn build` или работы на VPS.
Генератор не перезаписывает оригиналы и не удаляет старые версии с хешем:
они могут использоваться посетителями с ранее загруженной страницей.
Тесты проверяют соответствие хешей и размеров, MP4 faststart и отсутствие аудио.

Локальный `<video>` работает и без server streaming; `.next` выбрана как режим
размещения всего приложения. [Рекомендации Next.js по видео](https://nextjs.org/docs/app/guides/videos).

## Изображения

Оригиналы в `public/` сохранены. Страница использует заранее подготовленные
AVIF и WebP из `public/donetsk/images/`. Браузер выбирает размер через
`srcset` / `sizes`; версии крупнее оригинала не создаются. Фотографии ниже Hero
загружаются лениво.

Глобальное отключение оптимизации `next/image` удалено. На главной странице и
в общем блоке оборудования Next.js подбирает размер через `sizes` и отдаёт
оптимизированные изображения через `/_next/image`. Подготовленные `<picture>`
на страницах Донецка продолжают использовать собственные AVIF/WebP.

В блоке «Транспорт» используется общий `VehicleGallery` с тем же `Carousel`,
что и на `/donetsk/moskva`. Три фотографии Sprinter показываются целиком в
формате 3:4. Исходные JPG хранятся в `public/donetsk/sprinter/`, WebP-копии имеют
ширину 480/960 px. Для их обновления: `node scripts/optimize-sprinter-images.mjs`.
У этих имён нет хеша: правило годового immutable-кеша к ним не применяется.

После замены исходных фотографий выполните:

```sh
npm run optimize:donetsk-images
```

Команда использует Sharp, поставляемый с Next.js, и обновляет
`app/donetsk/images.generated.ts`. Новые изображения и этот файл нужно включить
в коммит. Генерация не требуется при каждом запуске или сборке: готовые файлы
хранятся в репозитории.

Имена содержат хеш содержимого. В Nginx перед сервером Next.js для этих файлов используйте
`Cache-Control: public, max-age=31536000, immutable`, как в
[примере Nginx](../deploy/nginx-next.conf.example). Старые URL не следует
перезаписывать другими изображениями.

## Клиентский код

- Телефон, мессенджеры и кнопки формы размечены `data-donetsk-goal` и
  `data-cta-position`. Эти атрибуты используются единым обработчиком кликов.
- Обычные ссылки на главную не запускают предзагрузку других страниц.
- Общий `app/not-found.tsx` намеренно не импортирует интерактивные Header/Footer:
  Next.js включает корневую 404-границу в данные каждой страницы, а эти импорты
  подтягивали на /donetsk меню, карусели и другие зависимости главной.
- Серверный `SiteAnalytics` подключает загрузчик Метрики через `next/script`
  с `strategy="afterInteractive"` и постоянным `id`. На `/donetsk` библиотека
  `tag.js` загружается асинхронно после `load`, в свободное время браузера
  (`requestIdleCallback` с таймаутом 2000 мс; без него — `setTimeout`).
  Маленький клиентский `MetrikaPageViews` отслеживает завершённые переходы
  App Router, включая назад/вперёд и изменение поисковых параметров.
  Инициализация с `defer: true` выполняется один раз; первый просмотр и переходы
  отправляются через `hit`, без второго автоматического просмотра.
  Команды `init`, `hit` и `reachGoal` сохраняются в стандартной очереди `ym`
  до загрузки счётчика. На остальных страницах библиотека подключается сразу
  при выполнении `afterInteractive`. Для отключённого JS есть `noscript`-пиксель.
- `LazyContactModal` сразу показывает закрываемое окно ожидания с телефоном
  и мессенджерами. При ошибке загрузки кода формы доступен повтор; отменённое
  открытие не возобновляется после получения чанка.
- Каталог услуг остаётся на сервере: клиентское меню получает только названия
  и адреса ссылок. Статичные карточки каруселей и FAQ не требуют отдельных
  клиентских компонентов.
- В мобильной нижней панели убрано постоянное размытие прокручиваемого фона.

### Размер начального JavaScript после ревью

Сравнение production-сборок Next.js 16.4.2 до и после текущего ревью:

| Страница | До, gzip | После, gzip |
| --- | ---: | ---: |
| `/` | 208 923 байт | 205 936 байт |
| `/donetsk` | 197 215 байт | 200 847 байт |
| `/donetsk/moskva` | 197 215 байт | 200 847 байт |
| `/prices` | 206 773 байт | 205 125 байт |

Подсчитана сумма gzip-размеров уникальных внешних JS-файлов из начальных
`script src` в серверном HTML. HTML/RSC, медиа, внешняя Метрика и отложенный
код формы в замер не входят. Это сравнение состава сборки, не показатель
Core Web Vitals. Начальный JS страниц Донецка вырос на 3 632 байта gzip:
добавлены доступная оболочка ожидания формы и наблюдение за SPA-переходами.
На главной и странице цен удаление клиентского каталога и статичной логики
компенсировало эти добавления.

## CSS-анимации Донецка

`app/donetsk/DonetskMotion.module.css` подключён только к серверной странице
`/donetsk`. Новых Client Components, зависимостей и обработчиков scroll нет.

- При загрузке рисуется линия под названием города и появляется маленький бейдж
  `24/7`. H1, основной текст, CTA и видео не скрываются анимацией.
- Карточки ниже первого экрана смещаются вверх на 14 px по мере входа в экран.
  Это `animation-timeline: view()` внутри `@supports`: без поддержки браузером
  карточки статичны. Их opacity всегда равна 1; прокрутка назад обращает движение.
- У навигации есть анимированное подчёркивание, у кнопок — отклик на нажатие.
  FAQ остаётся нативным `<details>`; коротко анимируется только текст ответа,
  а не его высота.
- `prefers-reduced-motion` отключает CSS-анимации и плавную прокрутку на странице;
  видео можно поставить на паузу нативными контролами.
  Добавлены ссылка пропуска шапки, focus-visible и учёт нижней safe area.

Корневой wrapper использует `overflow-x: clip`, а не `overflow: hidden`:
hidden создавал бы отдельный scroll container и мешал работе `view()`.
По той же причине класс reveal нельзя переносить внутрь блоков с overflow-hidden.

При историческом сравнении production-сборок Turbopack до/после добавления
CSS-анимаций (до видео и галереи Sprinter): размер начальных
JS-файлов в gzip не изменился (177 167 байт), общий CSS вырос на 1 011 байт gzip.
Появился один дополнительный CSS-файл. Это сравнение файлов сборки, а не замер
скорости загрузки на телефоне. H1, четыре JSON-LD блока и девять tel-ссылок сохранены.

Для ручной проверки: прокрутить карточки вперёд/назад, открыть FAQ, пройти страницу
клавишей Tab и повторить с включённым уменьшением движения в настройках системы.
В браузере без поддержки scroll-анимаций карточки должны оставаться видимыми.
Справка: [CSS animation-timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline),
[производительность анимаций](https://web.dev/articles/animations-guide).

### Отображение без JavaScript

`check:build` проверяет H1 всех страниц sitemap в видимом `main` сборки
`.next/server/app`. Для Москвы проверяются также основные разделы страницы.
Режим `next start` сохраняет предварительный рендеринг этих страниц. Поведение
без JavaScript дополнительно проверяется в браузере.

### Ожидание перехода на медленном соединении

Переходы на `/donetsk` и `/donetsk/moskva` используют общий `DonetskRouteLink`.
Единственный маленький клиентский компонент `RouteLinkStatus` получает реальное
состояние перехода из [`useLinkStatus`](https://nextjs.org/docs/app/api-reference/functions/use-link-status).
Пока Next.js получает страницу, посетитель видит сообщение «Открываем страницу…»
и название направления. Исходный контент, телефон и мессенджеры остаются доступны.
Карточка не захватывает фокус и не перехватывает нажатия.

Карточка выводится через portal в `document.body`, чтобы анимация и прокрутка
мобильного меню не обрезали её. Для скринридера внутри ссылки остаётся один
`role="status"`; визуальная карточка не дублирует объявление. У завершённого или
отменённого перехода индикатор исчезает вместе с `pending`.

Декоративная индикация появляется через 150 мс, чтобы не мигать при быстрых
переходах. Сама навигация не задерживается; искусственных процентов и таймеров
загрузки нет. `prefers-reduced-motion` отключает анимацию. Ссылки остаются
обычными HTML-якорями без JavaScript и поддерживают открытие в новой вкладке.
У взаимных ссылок посадочных страниц `prefetch={false}` сохраняет прежний расход
мобильного трафика: соседняя страница не скачивается только из-за появления ссылки
на экране. Входящие ссылки из основного меню, Footer и юридических страниц
сохраняют прежнюю предзагрузку Next.js. Если данные уже получены, переход проходит
сразу и индикатор не показывается.

Обычные серверные `loading.tsx` для обеих страниц проверены в production на
Next.js 16.4.2. В этой сборке они помещали готовый `main` в скрытый контейнер
Suspense: в Chrome без JavaScript оставалась только заглушка. Проверка
`check:build` обнаружила это, поэтому маршрутные loading-файлы не используются.
Проверки SEO не ослаблены; CSS-обходов для скрытых контейнеров React нет.

При прямом заходе обе страницы сразу отдают готовый HTML. Индикатор перехода
не ждёт загрузки фото или видео и не ускоряет передачу данных сам по себе.
Обычный [`loading.tsx`](https://nextjs.org/docs/app/api-reference/file-conventions/loading)
стоит повторно рассмотреть при появлении асинхронных данных в маршрутах или
после обновления Next.js, сохранив проверку production HTML и режим без JavaScript.

## Предыдущие замеры до добавления видео и галереи

Сравнение выполнялось на двух отдельных production-сборках одной версии
Next.js 16.1.5 (`next build --webpack`), в Chromium, без трафика Метрики:

| Начальная загрузка | До | После |
| --- | ---: | ---: |
| JavaScript, сжатые тела ответов | 158 КБ | 119 КБ |
| Количество начальных JS-файлов | 13 | 6 |
| Переданные ресурсы в мобильном Lighthouse, три прогона | 292 КБ | 188 КБ |

КБ в таблице — 1000 байт. Трафик Метрики исключён из обеих версий, браузерный
кеш перед замерами очищался. Количество начальных ресурсов может меняться
из-за порога ленивой загрузки изображений и предзагрузки ссылок.

Это локальные замеры, а не обещание времени загрузки на production. Время
первой отрисовки зависит также от сервера, сети, кеша и устройства. До сравнения
реальных показателей нужно опубликовать сборку и повторить проверку на сайте.
